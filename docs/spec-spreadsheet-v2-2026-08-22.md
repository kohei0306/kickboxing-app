## 1. 背景

参加表と資金管理を分析に使おうとしたところ、次の4点で作業が止まった。

1. 参加表の日付に年がない（行3が「8/22」のみ）
2. 参加表95行目の合計が壊れている（列ごとに `COUNTIF(BR46:BR73)` のように範囲がバラバラで、大半の列が空）
3. 資金管理の費目列がずれている（オープングローブ・タオル・グローブ・清掃道具・スポーツ保険が会場費の列に、会場費7,200円が道具の列に）

加えて、費用（A〜F列）と収入（H〜J列）という**別テーブルが1シートに同居**している。

## 5. 実装手順（破壊を伴わない入れ替え方式）

既存タブを直接編集せず、新タブを作ってから名前を入れ替える。どの時点でもデータは失われない。

1. 新タブ `参加表_v2` `入金` `支出` `収支サマリー` を作成
2. 旧データを移行
3. 検証（§8）に合格することを確認
4. 耕平さんの確認を取る
5. `参加表` → `参加表_旧` にリネーム、`参加表_v2` → `参加表` にリネーム
6. `資金管理` → `資金管理_旧` にリネーム（削除はしない）
7. `参加表_旧` `資金管理_旧` は非表示にして残す

## 6. 参加表 v2 の仕様

マトリクス形式（1行＝1名、1列＝1開催、セル＝出席チェックボックス）は維持する。

### 6.1 レイアウト

**固定表示**: 行1〜9、列A〜H

| 行 | 内容 | 備考 |
|---|---|---|
| 1 | 年 | 2023〜。新設 |
| 2 | 月 | |
| 3 | 日 | 既存の値をここへ |
| 4 | 日付 | `=IFERROR(DATE(I$1,I$2,I$3),"")` 実日付。期間集計に使う |
| 5 | 時間帯 | 昼 / 夜。夜練に対応。既存分はすべて「昼」 |
| 6 | 会場 | 武道館 / まちなか / 文化 / その他。既存分は空欄 |
| 7 | 出席者数 | `=COUNTIF(I$10:I$200,TRUE)` |
| 8 | うち課金対象 | `=COUNTIFS(I$10:I$200,TRUE,$A$10:$A$200,TRUE)` |
| 9 | 列見出し | |
| 10〜 | 名簿 | 200行目まで見込む |

| 列 | 内容 | 備考 |
|---|---|---|
| A | 課金対象 | チェックボックス。部長・副会長を FALSE |
| B | 区分 | 部長 / 副部長 / 会員 / 回数券 / 一般 / 体験 |
| C | 名前 | |
| D | 状態 | 現役 / 休会 / 退会 |
| E | 通算 | `=COUNTIF(I10:GZ10,TRUE)` |
| F | 直近1年 | `=COUNTIFS($I$4:$GZ$4,">="&EDATE(TODAY(),-12),$I$4:$GZ$4,"<="&TODAY(),I10:GZ10,TRUE)` |
| G | 直近3ヶ月 | `=COUNTIFS($I$4:$GZ$4,">="&EDATE(TODAY(),-3),$I$4:$GZ$4,"<="&TODAY(),I10:GZ10,TRUE)` |
| H | 最終参加日 | `=IFERROR(MAXIFS($I$4:$GZ$4,I10:GZ10,TRUE),"")` 日付書式 |
| I〜GZ | 開催日ごとの出席 | チェックボックス。新しい開催は右へ追加 |

**日付列の確保幅**: I列からGZ列までの200列。既存88列を移行するので残り112列。月5回開催で約2年分の余裕がある。足りなくなったら列を追加し、E〜H列の数式の範囲を広げる。

### 6.2 設計判断の理由

- **集計列を名前の直後（E〜H）に置く**: 現行は「総数」がCR列（96列目）にあり画面外だった
- **A列「課金対象」**: 部長・副会長を分析のたびに手で除外していた手間をなくす
- **D列「状態」**: 現行は54行が非表示。非表示ではなくフィルタで扱えるようにする
- **合計を上部（行7〜8）に置く**: 名簿に行を追加しても位置が動かない
- **COUNTIF の判定値**: 現行は `$A$4`（ミヤさんの行のセル）を基準にしていた。v2ではリテラル `TRUE` を使い、基準セルへの依存をなくす

## 7. 資金管理 v2 の仕様（3タブに分割）

### 7.1 `入金` タブ

| 列 | 内容 |
|---|---|
| A | 日付（YYYY/MM/DD。不明なら空欄） |
| B | 名前（参加表C列と同じ表記） |
| C | 区分（プルダウン: 回数券 / 都度 / 初回体験 / 年会費 / スポーツ保険 / その他） |
| D | 金額 |
| E | 備考 |

### 7.2 `支出` タブ

| 列 | 内容 |
|---|---|
| A | 日付（不明なら空欄） |
| B | 費目（プルダウン: 会場費 / エアコン / 道具 / HP / スポーツ保険 / その他） |
| C | 内容 |
| D | 金額 |

### 7.3 `収支サマリー` タブ

数式のみ。手入力しない旨をA1に明記する。

- 年度別サマリー（収入・支出・収支）
- 区分別収入 / 費目別支出
- 月次テーブル（月 / 開催回数 / のべ参加 / 1回平均 / 収入 / 支出 / 収支）
- **日付不明の行を別枠で表示**（§7.4）

集計は列全体参照を使い、行追加で壊れないようにする。

```
=SUMIFS(入金!D:D, 入金!C:C, "回数券", 入金!A:A, ">="&開始日, 入金!A:A, "<="&終了日)
```

### 7.4 日付不明の扱い

現行の入金52件のうち、日付が入っているのは10件程度。日付を推測して埋めることはしない。

- 日付が空欄の行は月次テーブルに乗らない
- 収支サマリーに「日付不明」行を設け、そこに含まれる件数と金額を明示する
- 計算式: `=SUMIFS(入金!D:D,入金!C:C,区分) - SUMIFS(入金!D:D,入金!C:C,区分,入金!A:A,"<>")`

## 8. データ移行

### 8.1 参加表

**年の復元**（検証済み）

行3の88列（F3:CQ3）を左から走査し、月が前列より小さくなった箇所を年の変わり目とする。全4区間がいずれも月について単調増加であることを確認済み。

| 区間 | 列 | 日付 | 年 | 開催数 |
|---|---|---|---|---|
| 1 | F〜V | 9/2〜12/23 | 2023 | 17 |
| 2 | W〜BE | 1/13〜12/21 | 2024 | 35 |
| 3 | BF〜BZ | 1/11〜11/22 | 2025 | 21 |
| 4 | CA〜CQ | 1/17〜8/22 | 2026 | 15 |

最終列 CQ の 8/22 が本日（2026-08-22）であることを起点に遡って確定。開始が2023年9月で、資金管理の最初の収入記録「2023０９」とも一致する。

**その他の移行**

- 出席値（F4:CQ90 の TRUE/FALSE）はそのまま新レイアウトの日付列へ転記
- 旧D列（区分）→ 新B列、旧E列（名前）→ 新C列
- 課金対象: 部長（ミヤさん）と副会長（シンさん）を FALSE、他は TRUE
- 状態: **現行で非表示になっている行を「休会」**、表示されている行を「現役」とする。耕平さんの既存の判断を保つため
- 時間帯: 既存分はすべて「昼」
- 旧95行目（壊れた合計）・96行目（日付コピー）・98行目（2026-08-22に追加した出席者数）は移行しない。行7〜8で作り直す

### 8.2 資金管理 → 入金

旧H〜J列の52件を移行する。

**区分の判定**

| 条件 | 区分 |
|---|---|
| 名前に「保険」を含む | スポーツ保険 |
| 金額 3,980 または 7,960 | 回数券 |
| 金額 500 | 初回体験 |
| 上記以外 | 都度（備考に元の記載を残す） |

**注意が必要な行**: 金額2,000円の行が複数あるが、内訳が一様でない。「松村パーソル」「たいよう君」「ゆーし君パーソル」はPBD（パーソル）区分の料金、「水さん回数」「綿島4回券」「森越4回券」「坂口祥子4回件」は4回券（旧料金）と読める。**機械的に「都度」にまとめず、1件ずつ元の記載を見て判断し、判断できないものは備考に元の文字列をそのまま残す。**同様に5,000円・7,000円の行も旧料金体系の可能性があるため個別に確認する。

**日付の復元**

`AppData!A1` の JSON 内 `purchases` 配列に、日付つきの購入記録が37件ある（2024-10-26〜2026-08-22、すべて3,980円、`memberId` と `name` つき）。これを名前で照合して回数券の日付を補う。

優先順位:
1. 旧H列に日付がある → それを正規化（`202507` → 2025/07/01 など、日までわからない場合は月初、備考に「日付は月のみ判明」と明記）
2. AppData の purchases に一致する名前・金額がある → その日付
3. どちらもない → **空欄のまま**、備考に「日付不明」

## 11. リスクと対応

| リスク | 対応 |
|---|---|
| GASが参加記録タブを更新している | 参加記録タブを触らない |
| GASが参加表・資金管理を参照している | 調査の結果その形跡はない。加えて旧タブをリネームして残すため、万一参照があっても`参加表_旧`として復元できる |
